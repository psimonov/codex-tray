# Контекст проекта

## Поведение приложения

- Приложение запускается скрытым и показывает только значок в системном трее Windows.
- Панель показывается при наведении на значок и скрывается после ухода курсора.
  Контекстное меню позволяет включить запуск вместе с Windows и закрыть приложение.
- При открытии контекстного меню информационная панель скрывается, чтобы не
  перегружать область системного трея.
- Автозапуск хранится в пользовательском разделе Windows `Run`; путь вычисляется
  из текущего исполняемого файла и не зависит от папки установки.
- Системная всплывающая подсказка значка отключена.
- Процент означает оставшуюся квоту Codex. Полоса и квадратный значок работают
  как опорожняющийся стакан: при 100% область заполнена, затем уровень опускается
  сверху вниз и при 0% остаётся пустой.
- Метрики панели расположены в стабильных строках `Ключ: значение`, поэтому
  опрос данных не меняет размеры и положение окна. Используется системный шрифт
  Windows с учётом DPI.
- Панель учитывает светлую/тёмную тему, цвет акцента и настройку прозрачности
  Windows. Для критически низкого остатка сохраняются предупреждающие цвета.

## Состояния выполнения

Интерфейс различает загрузку, обновление, готовность, исчерпанный лимит,
необходимость входа, отсутствие подписки/доступа, отсутствие исполняемого файла
`codex` в `PATH` и общую ошибку app-server. В исполняемый файл встроены значки
этих состояний и уровней квоты 0, 5, 25, 50, 75, 95 и 100 процентов.

## Авторизация и получение данных

Приложение поддерживает постоянное соединение с установленным `codex app-server`,
однократно вызывает `account/read` и `account/rateLimits/read`, затем получает
изменения через `account/rateLimits/updated`. Используется сессия Codex CLI текущего
пользователя ОС. Приложение не запрашивает API-ключ и напрямую не читает и не
копирует `~/.codex/auth.json`.

## Упаковка и переносимость

Команда `cargo build --release` создаёт один файл `codex-tray.exe`; все иконки
и ресурсы встроены внутрь. Установленная команда `codex` остаётся внешним
условием выполнения.

Опрос Codex и модели данных отделены от платформенной границы `src/platform.rs`.
Сейчас реализован только Windows-backend. Будущие реализации для macOS и Linux
должны сохранить канальный контракт и семантику квоты. Код не содержит
процессорных intrinsics и рассчитан на последующую сборку для Windows x86-64 и
ARM64.
